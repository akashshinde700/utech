    31→    63→
    32→    64→**Before writing ANY ReportLab code, answer this question:**
    33→    65→
    34→    66→> **Does this document have a Table of Contents?**
    35→    67→
    36→    68→| Answer | DocTemplate | Build Method | TOC Implementation |
    37→    69→|--------|-------------|--------------|--------------------|
    38→    70→| **YES** | `TocDocTemplate` | `doc.multiBuild(story)` | `TableOfContents()` + heading `bookmark_name/level/text/key` attributes |

    41→    73→**⚠️ If you answered YES, these are ALL mandatory — missing any one = broken TOC:**
    42→    74→
    43→    75→```python
    44→    76→# 1. MUST define TocDocTemplate (NOT SimpleDocTemplate)
    45→    77→class TocDocTemplate(SimpleDocTemplate):
    46→    78→    def afterFlowable(self, flowable):
    47→    79→        if hasattr(flowable, 'bookmark_name'):
    48→    80→            level = getattr(flowable, 'bookmark_level', 0)
    49→    81→            text = getattr(flowable, 'bookmark_text', '')
    50→    82→            key = getattr(flowable, 'bookmark_key', '')
    51→    83→            self.notify('TOCEntry', (level, text, self.page, key))
    52→    84→
    53→    85→# 2. MUST add TableOfContents to story
    54→    86→toc = TableOfContents()
    55→    87→toc.levelStyles = [toc_level0, toc_level1]  # define your styles
    56→    88→story.append(toc)
    57→    89→story.append(PageBreak())
    58→    90→
    59→    91→# 3. MUST set bookmark attributes on every heading
    60→    92→def add_heading(text, style, level=0):
    61→    93→    key = f'h_{hashlib.md5(text.encode()).hexdigest()[:8]}'
    62→    94→    p = Paragraph(f'<a name="{key}"/>{text}', style)
    63→    95→    p.bookmark_name = key
    64→    96→    p.bookmark_level = level
    65→    97→    p.bookmark_text = text
    66→    98→    p.bookmark_key = key
    67→    99→    return p
    68→   100→
    69→   101→# 4. MUST use multiBuild (NOT build)
    70→   102→doc = TocDocTemplate(output_path, pagesize=A4, ...)
    71→   103→doc.multiBuild(story)
    72→   104→```

   184→   216→## Step 3: EDIT - Content Transformation
   185→   217→
   186→   218→**Before writing any code, restructure raw text into visual roles.** This is the most impactful quality step - skipping it produces "Word document with a PDF extension".
   187→   219→
   188→   220→### 3a. Typographic Role Extraction
   189→   221→
   190→   222→Parse raw text and categorize content into visual roles:
   191→   223→
   192→   224→| Role | ReportLab Mapping | Description |
   193→   225→|------|------------------|-------------|
   194→   226→| **Hero / Display** | Cover title (36-42pt) or section opener | 1-5 words, the emotional hook |
   195→   227→| **Kicker / Eyebrow** | Subtitle or section intro (10-12pt, muted) | Tiny context line above main heading |
   196→   228→| **Data Sculpture** | CalloutBox or bold stat block | Extract impactful numbers (97%, $4.2M, -45ms) |
   197→   229→| **Pull Quote** | BlockQuote (italic + left indent 24pt + accent border) | Most provocative sentence, standalone |
   198→   230→| **Body** | Standard paragraph | Everything else |
   199→   231→
   200→   232→**Rule**: Before writing any body paragraph, scan for numbers with units. Every metric like "revenue grew by 12%" or "latency dropped to 45ms" MUST be extracted into a CalloutBox or metrics table - never buried in paragraph prose. See §Data-to-Ink Ratio Rules below.
   201→   233→
   202→   234→### 3b. Section Pacing
   203→   235→
   204→   236→- If any H1 section has **>400 words** of continuous body text without visual breaks, split into H2 subsections or insert a visual break (table, chart, callout)
   205→   237→- Aim for at least 1 visual element (table/chart/callout) per 2-3 pages of body text
   206→   238→- Dense text walls are the #1 sign of poor report design
   207→   239→
   208→   240→### 3c. Content Sanitization for External Sources (MANDATORY when source is PDF/OCR/web)
   209→   241→
   210→   242→When content is extracted from an external PDF, OCR output, or web scrape, it may contain invisible garbage characters that cause garbled rendering. **You MUST sanitize the text content before writing it into any `Paragraph()` or `canvas.drawString()`.**
   211→   243→
   212→   244→This is different from `code.sanitize` (which cleans Python source code). Content sanitization cleans the **text data itself**.
   213→   245→
   214→   246→```python
   215→   247→import re
   216→   248→
   217→   249→def content_sanitize(text: str) -> str:
   218→   250→    """Strip invisible/control chars from externally-sourced text."""
   219→   251→    # Remove control chars (except \n \t)
   220→   252→    text = re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f\x7f]', '', text)
   221→   253→    # Remove zero-width chars
   222→   254→    text = re.sub(r'[\u200b-\u200f\u2028-\u202f\u2060\ufeff]', '', text)
   223→   255→    # Remove replacement char (upstream encoding error)
   224→   256→    text = text.replace('\ufffd', '')
   225→   257→    # Remove variation selectors
   226→   258→    text = re.sub(r'[\ufe00-\ufe0f]', '', text)
   227→   259→    # Remove private use area chars
   228→   260→    text = re.sub(r'[\ue000-\uf8ff]', '', text)
   229→   261→    return text
   230→   262→```
   231→   263→
   232→   264→**When to use:**
   233→   265→| Source | Must sanitize? |
   234→   266→|--------|---------------|
   235→   267→| User typed text in prompt | No (usually clean) |
   236→   268→| Extracted from PDF via `pdf.py extract.text` | **YES** |
   237→   269→| OCR output | **YES** |
   238→   270→| Web scrape / HTML strip | **YES** |
   239→   271→| LLM-generated content | No (usually clean) |
   240→   272→
   241→   273→⚠️ **Do NOT confuse** `code.sanitize` (Step 6, cleans Python code) with `content_sanitize()` (Step 3, cleans text data). They solve different problems.

   270→   302→## Character Safety Rule (MANDATORY)
   271→   303→
   272→   304→Three rules for safe character handling in ReportLab PDFs:
   273→   305→
   274→   306→**a) Superscripts and subscripts**: Use `<super>`/`<sub>` tags, never raw Unicode superscript/subscript characters (e.g., `\u00b2`, `\u2082`).
   275→   307→
   276→   308→**b) Emoji**: ReportLab cannot render emoji. If content contains emoji, use Creative brief (HTML + Playwright).
   277→   309→
   278→   310→**c) Font fallback for mixed CJK/Latin text (MANDATORY)**: After registering fonts, you **MUST** call `install_font_fallback()` once. This automatically wraps missing-glyph characters in `<font>` tags inside every `Paragraph()`. No manual `<font name="...">` wrapping needed for mixed Chinese-English text. **Skipping this call is the #1 cause of Helvetica garbled text in CJK documents.**
   279→   311→
   280→   312→**d) canvas.drawString / drawRightString CJK font rule (MANDATORY)**: `install_font_fallback()` only works on `Paragraph()` objects. It does NOT affect `canvas.drawString()` / `canvas.drawRightString()` / `canvas.drawCentredString()`. If the text passed to any `canvas.draw*String()` call contains CJK characters (Chinese/Japanese/Korean), you **MUST** call `canvas.setFont('NotoSerifSC', size)` (or another registered CJK font) before drawing. Using FreeSerif / Helvetica / Times for CJK canvas text = garbled output.
   281→   313→
   282→   314→```python
   283→   315→# ❌ WRONG — FreeSerif has no CJK glyphs, '科大讯飞' will be garbled
   284→   316→canvas.setFont('FreeSerif-Italic', 8)
   285→   317→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   286→   318→
   287→   319→# ✅ CORRECT — use CJK font for mixed text
   288→   320→canvas.setFont('NotoSerifSC', 8)
   289→   321→canvas.drawRightString(x, y, 'SZSE: 002230  ·  科大讯飞')
   290→   322→
   291→   323→# ✅ ALSO CORRECT — pure English text can use FreeSerif
   292→   324→canvas.setFont('FreeSerif-Italic', 8)
   293→   325→canvas.drawString(x, y, 'Prepared by Strategy Advisory Team')
   294→   326→```
   295→   327→
   296→   328→Mathematical/relational operators (×, ÷, ±, ≤, √, ∑, ≅, ∫, π, ∠, Δ, etc.) are safe to use as literal characters in `Paragraph()` - both Noto Sans SC and FreeSerif have these glyphs.
   297→   329→
   298→   330→| Need | Correct Method | Correct Example |
   299→   331→|------|---------------|---------|
   300→   332→| Superscript | `<super>` tag in `Paragraph()` | `Paragraph('10<super>2</super> × 10<super>3</super> = 10<super>5</super>', style)` |
   301→   333→| Subscript | `<sub>` tag in `Paragraph()` | `Paragraph('H<sub>2</sub>O', style)` |
   302→   334→| Bold | `<b>` tag in `Paragraph()` | `Paragraph('<b>Title</b>', style)` |
   303→   335→| Math operators | Literal char in `Paragraph()` | `Paragraph('AB ⊥ AC, ∠A = 90°, and ΔABC ≅ ΔDCF', style)` |
   304→   336→| Scientific notation | Combined tags in `Paragraph()` | `Paragraph('1.2 × 10<super>8</super> kg/m<super>3</super>', style)` |
   305→   337→
   306→   338→```python
   307→   339→from reportlab.platypus import Paragraph
   308→   340→from reportlab.lib.styles import ParagraphStyle
   309→   341→from reportlab.lib.enums import TA_LEFT, TA_CENTER, TA_JUSTIFY
   310→   342→
   311→   343→body_style = ParagraphStyle(
   312→   344→    name="ENBodyStyle",
   313→   345→    fontName="FreeSerif",
   314→   346→    fontSize=10.5,
   315→   347→    leading=18,
   316→   348→    alignment=TA_JUSTIFY,
   317→   349→)
   318→   350→
   319→   351→# CJK Body (Chinese documents)
   320→   352→cn_body_style = ParagraphStyle(
   321→   353→    name="CNBodyStyle",
   322→   354→    fontName="NotoSerifSC", fontSize=10.5, leading=18,
   323→   355→    alignment=TA_LEFT,      # ← NEVER TA_JUSTIFY for CJK
   324→   356→    wordWrap='CJK',         # ← MANDATORY for CJK
   325→   357→    firstLineIndent=2*4.5*mm,
   326→   358→)
   327→   359→
   328→   360→# Superscript: area unit
   329→   361→Paragraph('Total area: 500 m<super>2</super>', body_style)
   330→   362→
   331→   363→# Subscript: chemical formula
   332→   364→Paragraph('The reaction produces CO<sub>2</sub> and H<sub>2</sub>O', body_style)
   333→   365→
   334→   366→# Scientific notation
   335→   367→Paragraph('Speed of light: 3.0 × 10<super>8</super> m/s', body_style)
   336→   368→
   337→   369→# Combined
   338→   370→Paragraph('E<sub>k</sub> = mv<super>2</super>/2', body_style)
   339→   371→
   340→   372→# Bold heading
   341→   373→Paragraph('<b>Chapter 1: Introduction</b>', header_style)
   342→   374→
   343→   375→# Math symbols
   344→   376→Paragraph('When ∠ A = 90°, AB ⊥ AC and ΔABC ≅ ΔDEF', body_style)
   345→   377→```
   346→   378→
   347→   379→**Pre-generation check - before writing ANY string, ask:**
   348→   380→> "Does this string contain a character outside basic CJK or Mathematical/relational operators?"
   349→   381→> If YES → it MUST be inside a `Paragraph()` with the appropriate tag.
   350→   382→> If it is a superscript/subscript digit in raw unicode escape form → REPLACE with `<super>`/`<sub>` tag.
   351→   383→
   352→   384→**NEVER rely on post-generation scanning. Prevent at the point of writing.**
   353→   385→
   354→   386→**Encoding safety - before writing ANY content text:**
   355→   387→> "Does this string contain Japanese kana (の, が, は etc.) or rare Unicode symbols?"
   356→   388→> If YES → REPLACE with safe plain Chinese equivalents. Japanese kana (Hiragana U+3040-U+309F, Katakana U+30A0-U+30FF) frequently corrupt to U+FFFD (�) when code passes through LLM output, heredoc, or terminal encoding layers.
   357→   389→> Common safe replacements: `活の真鲷`→`活缔真鲷`, `盐烤の鲭鱼`→`盐烤鲭鱼`, `烤の鸡串`→`炭烤鸡串`.
   358→   390→> If the character is genuinely needed, verify it survives a full write→read round-trip with `open(file, encoding='utf-8')`.

   387→   419→from reportlab.pdfbase import pdfmetrics

   422→   454→### Font Configuration by Document Type
   423→   455→
   424→   456→**For Chinese PDFs:**
   425→   457→- Body text: `NotoSerifSC` (primary) — serif font with sharp, elegant strokes
   426→   458→- Headings: `NotoSerifSC-Bold` (MUST use for Chinese headings) — same family, bolder weight for clear hierarchy
   427→   459→- Code blocks: `SarasaMonoSC`
   428→   460→- Formulas/symbols: `DejaVuSans`
   429→   461→- **In tables: ALL Chinese content MUST use `NotoSerifSC`, numbers use `FreeSerif`**
   430→   462→- Fallback: `Noto Sans SC` (if NotoSerifSC unavailable)
   431→   463→
   432→   464→**For English PDFs:**
   433→   465→- Body text: `FreeSerif`
   434→   466→- Headings: `FreeSerif` (MUST use for English headings)
   435→   467→- Code blocks: `DejaVuSans`
   436→   468→- **In tables: ALL English content and numbers MUST use `FreeSerif`**
   437→   469→
   438→   470→**For Mixed Chinese-English PDFs:**
   439→   471→- Call `install_font_fallback()` once after registering fonts - it automatically wraps characters in `<font>` tags so you don't need to do it manually.
   440→   472→- If you still want manual control, you can use `<font name='...'>` tags, but the automatic fallback handles most cases.
   441→   473→
   442→   474→```python
   443→   475→import sys, os
   444→   476→sys.path.insert(0, os.path.join(os.path.dirname(__file__), 'scripts'))
   445→   477→from pdf import install_font_fallback
   446→   478→
   447→   479→# 1. Register fonts (as above)
   448→   480→# 2. Install fallback - one line, handles all mixed-language text
   449→   481→install_font_fallback()
   450→   482→
   451→   483→# 3. Just write naturally - no manual <font> wrapping needed!
   452→   484→en_style = ParagraphStyle(name="EN", fontName="FreeSerif", fontSize=10.5, leading=18)
   453→   485→cn_style = ParagraphStyle(name="CN", fontName="NotoSerifSC", fontSize=10.5, leading=18, wordWrap='CJK')
   454→   486→
   455→   487→Paragraph('MySQL、PostgreSQL、Redis', en_style)           # ✅ CJK comma auto-fallback to NotoSerifSC
   456→   488→Paragraph('Beijing (北京) has 21M people', en_style)       # ✅ CJK chars auto-fallback
   457→   489→Paragraph('价格:¥2,200~5,800/月', en_style)               # ✅ all CJK chars handled
   458→   490→Paragraph('《巴黎协定》签署于2015年', en_style)               # ✅ CJK book title marks handled
   459→   491→```
   460→   492→
   461→   493→**How it works:** `install_font_fallback()` monkey-patches `Paragraph.__init__` to scan each character against the font's `charToGlyph` table. Characters missing from the base font are automatically wrapped in `<font name="FallbackFont">`. The fallback chain is: English fonts → NotoSerifSC (primary) or Noto Sans SC (legacy), Chinese fonts → FreeSerif. For aesthetic optimization, Cyrillic text in NotoSerifSC/Noto Sans SC is automatically routed to FreeSerif (serif looks better for Cyrillic).

   482→   514→## Layout & Spacing Control
   483→   515→
   484→   516→### Page Breaks
   485→   517→
   486→   518→Follow the document type strategy defined in SOUL.md Rule 1.
   487→   519→
   488→   520→**Structural breaks (always - MANDATORY):**
   489→   521→- Between cover page and TOC - **cover must NEVER share a page with anything else**
   490→   522→- Between TOC and main content
   491→   523→- Between main content and back cover
   492→   524→
   493→   525→**Content breaks (by document type):**
   494→   526→- **Default (all document types)**: ❗ **Absolutely NEVER force page breaks before H1/H2** — content flows naturally, do not insert `PageBreak()` before section headings. This is an iron rule.
   495→   527→- Resume / contract / letter → No content page breaks
   496→   528→- Short article → No content page breaks
   497→   529→- **Exception 1**: Academic papers / textbooks / teaching plans → `PageBreak()` before each H1 is acceptable (only if user explicitly requests academic formatting)
   498→   530→- **Exception 2**: User explicitly requests page breaks between chapters
   499→   531→
   500→   532→**Anti-tear (mandatory — but with height limit):**
   501→   533→```python
   502→   534→from reportlab.platypus import KeepTogether
   503→   535→from reportlab.lib.pagesizes import A4
   504→   536→from reportlab.lib.units import inch
   505→   537→
   506→   538→# Maximum height for KeepTogether blocks: 40% of page height
   507→   539→# Blocks taller than this should NOT be kept together — they cause
   508→   540→# the preceding page to be mostly empty when the block gets pushed down.
   509→   541→MAX_KEEP_HEIGHT = A4[1] * 0.4  # ~336pt ≈ 12cm
   510→   542→
   511→   543→def safe_keep_together(elements):
   512→   544→    """Wrap elements in KeepTogether only if their total height is reasonable.
   513→   545→    If too tall, keep only the FIRST TWO elements together (e.g. title + table/image header)
   514→   546→    to prevent title-content separation, while letting the rest paginate naturally.
   515→   547→    """
   516→   548→    total_h = 0
   517→   549→    for el in elements:
   518→   550→        w, h = el.wrap(A4[0] - 2*inch, A4[1])
   519→   551→        total_h += h
   520→   552→    if total_h <= MAX_KEEP_HEIGHT:
   521→   553→        return [KeepTogether(elements)]
   522→   554→    elif len(elements) >= 2:
   523→   555→        # Keep at least title + first element together to prevent title orphaning
   524→   556→        return [KeepTogether(elements[:2])] + list(elements[2:])
   525→   557→    else:
   526→   558→        return list(elements)
   527→   559→
   528→   560→# Heading stays with first paragraph
   529→   561→story.extend(safe_keep_together([
   530→   562→    heading_paragraph,
   531→   563→    first_body_paragraph,
   532→   564→]))
   533→   565→
   534→   566→# Image + caption: keep together ONLY if image is small
   535→   567→story.extend(safe_keep_together([image, caption_paragraph]))
   536→   568→
   537→   569→# Table title + table: keep together ONLY if table is short
   538→   570→if len(table_data) <= 15:
   539→   571→    story.extend(safe_keep_together([table_title, table]))
   540→   572→else:
   541→   573→    # Long table: just keep title with the table start
   542→   574→    story.extend(safe_keep_together([table_title]))
   543→   575→    story.append(table)
   544→   576→```
   545→   577→
   546→   578→**⚠️ KEY INSIGHT:** `KeepTogether` is the #1 cause of “empty page with chart on next page”.
   547→   579→When a `KeepTogether` block is taller than the remaining space on the current page,
   548→   580→ReportLab pushes the **entire block** to the next page, leaving the current page mostly empty.
   549→   581→**Always use `safe_keep_together()` to cap the maximum block height.**
   550→   582→
   551→   583→**⚠️ Note:** Do NOT use `KeepWithNext` - it is unreliable in ReportLab 4.x.

   553→   585→### Vertical Spacing Standards
   554→   586→* Before tables: `Spacer(1, 18)` after preceding text
   555→   587→* After tables: `Spacer(1, 6)` before table caption
   556→   588→* After table captions: `Spacer(1, 18)` before next content
   557→   589→* Between paragraphs: `Spacer(1, 12)` (~1 line)
   558→   590→* Between H3 subsections: `Spacer(1, 12)`
   559→   591→* Between H2 sections: `Spacer(1, 18)` (~1.5 lines)
   560→   592→* Between H1 sections: `Spacer(1, 24)` (~2 lines)
